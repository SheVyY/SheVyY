## Selected work

### Netflixer.cz: editorial research, delivered to Slack

I designed the selection algorithm and built the complete Apify Actor in TypeScript. It is an independent project, separate from my work at Glow, and does not use Glow. A GitHub pipeline triggers the containerized Actor daily. It researches 20+ entertainment websites, selects the top 10 stories from the past 24 hours and sends the results directly to Slack.

I iteratively optimized the algorithm, combining multiple layers of semantic analysis, AI evaluation using Gemini, grouping, clustering and deduplication with the editorial team's domain knowledge. A single Slack card brings together Czech summaries, suggested headlines and clickable source links. Editors decide what to write and publish.

The editorial team uses it daily and saves time on research, though the saving has not been measured. It currently needs no routine maintenance.

## My work at Glow

Glow is a visual platform for workflow automation with AI. I joined as its fourth team member in December 2024, when it was called doFlo.

I help shape Glow's product direction with the team, propose and define features, and test their behavior. I write code, build tools and client automations, and write the full documentation.

I worked at Glow and TrustSoft in parallel after joining Glow in December 2024.

I advocated multiplayer for more than collaboration between teammates. I wanted people and AI agents to work on the same live canvas, including agents connected through MCP, so the person could see an automation take shape instead of waiting for a finished result.

My broader vision is for teams and AI agents to improve business processes together, with agents suggesting changes and helping users test and optimize them visibly on the canvas. I help define that behavior with the team and test how it works in practice.

People who do not write code should be able to build and run these automations. I want voice to be another way to do that. The principle is that neither the canvas nor the agent should block the user: people should be able to keep editing, review suggestions and respond when ready.

Shared editing is available today. The Workflow Assistant places steps and connections visibly while people keep editing. Its changes can replace the same content a person is editing. Voice control inside Glow is not available yet; the broader collaboration vision is still being developed. <a href="https://docs.getglow.ai/build/ai-features/workflow-assistant" target="_blank" rel="noopener noreferrer">Live canvas building →</a> · <a href="https://docs.getglow.ai/build/the-canvas/real-time-editing" target="_blank" rel="noopener noreferrer">Shared editing and overwrite behavior →</a>

I also proposed making AI-generated workflows visible on the canvas so people can understand the automations they use and help improve them. I define how these ideas should work with the team.

That also matters when an external agent builds through MCP. I wanted the canvas to make its work inspectable, rather than leave the person with only a chat transcript and a finished automation.

MCP is in Early Access and requires workspace enablement and an eligible role. External agents can inspect and edit automations. Saved changes and canvas synchronization have separate status; a successful save does not guarantee the editor has displayed it. Whole-automation testing through MCP is currently unavailable. <a href="https://docs.getglow.ai/manage/workspace-settings/mcp" target="_blank" rel="noopener noreferrer">MCP access, synchronization and testing limits →</a>

I built a travel intake automation now in client testing. I work directly with clients on requirements, onboarding and automation proposals, and handle support and sales demos. I write every page of the documentation at <a href="https://docs.getglow.ai" target="_blank" rel="noopener noreferrer">docs.getglow.ai</a> and record product walkthroughs.

### TrustSoft (2021 to 2025)

TrustSoft provides cloud consulting and managed services.

New client cloud environments took days to configure by hand and differed from one another. I built TrustSoft's governance framework above Amazon's AWS Control Tower: provisioning, security rules, integrations and operating documentation.

I started from AWS best practices and refined the framework through work on large client projects. Each project needed a documented foundation that its development and DevOps teams could build on, rather than a fresh infrastructure design every time.

I wrote Terraform components and modules where the ones we needed did not exist. I documented the architecture, setup and operation in full, so the baseline could be reused across projects rather than depend on my involvement in each deployment.

The framework became TrustSoft's standard for almost all projects and the backbone of Cloud Foundation across 15+ enterprise estates. These included Partners Bank, Eurowag and Acrelec, with new environments provisioned in hours. I presented the governance approach in Switzerland.

The documented baseline made new projects much faster to set up. It later evolved into a modular framework that TrustSoft still uses in paid client projects.

I wrote the documentation that helped TrustSoft obtain its Amazon QuickSight Delivery Partner designation. This was a company-level AWS service validation, separate from my personal certifications. <a href="https://aws.amazon.com/blogs/apn/say-hello-to-165-new-aws-competency-service-delivery-service-ready-and-msp-partners-added-in-august/" target="_blank" rel="noopener noreferrer">AWS announcement naming Trustsoft as a QuickSight Delivery Partner →</a>

Through TrustSoft, I built the full AWS setup for internal dashboarding across EPH's group companies and presented it to leadership at their Prague headquarters. It did not go into production at EPH because the group changed its strategy to Azure. TrustSoft kept the prototype and developed it into a FinOps dashboard it sold to other customers.

I built disposable AWS environments at TrustSoft for training people from other companies. Participants worked in test accounts that were discarded after training. I handed the system over when I left; I don't know whether it is still used. In Switzerland, people from AWS were surprised that I had built them.
